## Overview

**Contrib** helps developers contribute to unfamiliar open-source repositories with greater confidence.

The frontend provides the interface for submitting a public GitHub repository, exploring issue analysis, understanding relevant code, reviewing suggested fixes, and asking follow-up questions through repository chat.

Instead of navigating an unfamiliar codebase without direction, contributors can use Contrib to discover where to start and understand the changes they may need to make.

## Features

- **Repository Input** — Enter a public GitHub repository URL to begin.
- **Issue Analysis** — Submit an issue for structured analysis by the backend.
- **Relevant Code Context** — Explore files and code context identified by the retrieval pipeline.
- **Code Explanations** — Understand the relevant implementation and the reasoning behind a suggested solution.
- **Suggested Patches** — Review an optional code diff generated by the backend.
- **Repository Chat** — Ask follow-up questions about the indexed codebase.
- **Terminal-Inspired UI** — A minimal dark interface with neon-green accents, designed around the developer workflow.

## How It Works

```text
┌──────────────────────────────┐
│          React UI            │
│       App.jsx                │
│       Chatbox.jsx            │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│         Backend API          │
│  POST /api/analyze-issue     │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│    Multi-Agent Pipeline      │
│                              │
│    1. Issue Analyzer         │
│    2. Retrieval Agent        │
│    3. Reasoning Agent        │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│       Analysis Results       │
│                              │
│  Relevant files and context  │
│  Code explanations           │
│  Contribution steps          │
│  Optional suggested patch    │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│     React UI + Repository    │
│             Chat             │
└──────────────────────────────┘
```

The frontend handles user interaction and presentation. Repository ingestion, code retrieval, reranking, issue reasoning, and patch generation are handled by the backend services.

## Getting Started

### Prerequisites

- Node.js and npm
- Git
- Access to the Contrib backend for issue-analysis functionality

### 1. Clone the Repository

```bash
git clone <repository-url>
cd <repository-directory>/frontend
```

Replace the placeholders with your repository URL and frontend directory path.

### 2. Install Dependencies

```bash
npm install
```

### 3. Configure the Backend

Ensure the Contrib backend is running and the frontend is configured to use its API address.

The issue-analysis endpoint is:

```text
POST /api/analyze-issue
```

Use the API configuration expected by the existing frontend implementation. Do not commit private credentials or environment-specific secrets.

### 4. Start the Development Server

```bash
npm run dev
```

Vite will display the local development URL in the terminal.

## Development Notes

- Vite supports Hot Module Replacement (HMR) for a fast development workflow.
- Keep API communication and UI rendering responsibilities clearly separated.
- Handle loading states, failed requests, and invalid repository or issue URLs gracefully.
- Present retrieved files and generated patches clearly so contributors can inspect the suggested changes.
- Treat generated patches as suggestions that should be reviewed and tested before use.
